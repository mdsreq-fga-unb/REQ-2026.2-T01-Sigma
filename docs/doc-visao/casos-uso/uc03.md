# UC03 - Gerenciar Quadros de Avisos

[← Voltar para o Painel de Casos de Uso](index.md) • [Catálogo Unificado de Requisitos](../8_requisitos.md)

## 1. Atores

**Atores principais:** Equipe Administrativa (Secretárias, Coordenadoras e Diretora).

## 2. Objetivo

Permitir que a equipe administrativa envie avisos rápidos pelo sistema SIGMA, exiba notificações ativas e apague notificações em seu próprio espaço de forma definitiva, facilitando a comunicação interna, o trabalho em equipe e a coordenação do time da Creche Estação Vida.

## 3. Pré-condições

1. O ator deve estar autenticado no sistema SIGMA.
2. A conta do ator deve estar com o status "Ativo".
3. A sessão do ator não pode ter excedido 30 minutos de inatividade contínua.
4. O ator deve acessar a seção referente ao quadro de avisos na interface.
5. O sistema deve possuir conexão ativa com o backend (FastAPI/Python).
6. O backend deve estar integrado ao banco de dados PostgreSQL.

## 4. Fluxo Principal

**FP01 - Lançar Aviso no Quadro (RF01, RF02)**

1. O ator acessa a seção do Quadro de Avisos. 
2. O sistema identifica o perfil do ator autenticado. 
3. O sistema valida se o ator possui perfil da equipe administrativa. (FE01)
4. O sistema apresenta o formulário de criação de aviso. 
5. O ator preenche obrigatoriamente o assunto e a descrição do aviso. (RN09)
6. O sistema registra automaticamente a data atual e o autor responsável pela criação. (RN09)
7. O ator confirma a publicação do aviso. (FE04)
8. O sistema valida os dados obrigatórios informados. (RN09, FE02)
9. O sistema registra o aviso no banco de dados. (FE03)
10. O sistema disponibiliza o aviso no quadro para todos os usuários autorizados da equipe administrativa. 
11. O sistema exibe uma mensagem de sucesso informando que o aviso foi publicado.

## 5. Fluxos Alternativos

**FA01 - Exibir Avisos Ativos (RF03)**

1. O ator acessa a página inicial ou a seção do quadro de avisos. 
2. O sistema identifica o perfil do ator autenticado. 
3. O sistema busca os avisos ativos disponíveis no banco de dados, ordenados por data. (FE03)
4. O sistema exibe a lista de notificações ativas no quadro de avisos.
5. O ator visualiza os avisos. 

**FA02 - Apagar Aviso de Forma Definitiva (RF04)**

1. O ator acessa o quadro de avisos com as notificações ativas. 
2. O ator seleciona o aviso que deseja apagar. 
3. O ator aciona a opção de exclusão. 
4. O sistema remove o aviso de forma definitiva do espaço visual do usuário. (FE03)
5. O sistema atualiza o quadro de avisos, deixando de exibir o item apagado. 

## 6. Fluxos de Exceção

**FE01 - Acesso Não Autorizado (RF01)**

1. Um usuário não pertencente à equipe administrativa tenta acessar a seção de gerenciamento do quadro de avisos. 
2. O sistema identifica que o perfil não possui permissão. 
3. O sistema bloqueia o acesso e não exibe a funcionalidade de gerenciamento do quadro. 

**FE02 - Dados Obrigatórios Ausentes (RF02)**

1. O ator tenta publicar um aviso sem preencher o assunto e/ou a descrição. 
2. O sistema identifica a ausência dos dados obrigatórios. (RN09)
3. O sistema impede a publicação do aviso. 
4. O sistema destaca os campos inválidos e exibe mensagem orientando o preenchimento correto.

**FE03 - Falha de Conectividade (RF02, RF03, RF04)**

1. O ator tenta publicar, listar ou apagar um aviso sem conexão com o backend. 
2. O sistema não consegue concluir a operação. 
3. O sistema exibe uma mensagem de falha de conexão. 
4. O sistema orienta o ator a tentar novamente mais tarde. 

**FE04 - Sessão Expirada por Inatividade (RF07)**

1. O ator tenta confirmar o lançamento de um aviso ou excluí-lo após 30 minutos de inatividade. 
2. O sistema identifica que a sessão do usuário expirou. (RN17)
3. O sistema impede a operação. 
4. O sistema encerra a sessão, descarta as alterações não salvas e redireciona o ator para a tela de login. 

## 7. Regras de Negócio

| ID | Regra de Negócio | Justificativa | Requisitos Relacionados |
|---|---|---|---|
| [RN09](../Regras-Negocio.md#rn09) | A criação de um aviso exige data e autor registrados e só poderá ser publicado quando o assunto e descrição estiverem preenchidos. | Garante identificação e rastreabilidade. | [RF02](../8_requisitos.md#req-rf02) |
| [RN17](../Regras-Negocio.md#rn17) | A sessão do usuário deve ser encerrada após 30 minutos de inatividade contínua. | Protege dados sensíveis em abandono de terminal. | [RF07](../8_requisitos.md#req-rf07), [RNF01](../8_requisitos.md#req-rnf01), [RNF02](../8_requisitos.md#req-rnf02) |
| [RN18](../Regras-Negocio.md#rn18) | Apenas contas com status "Ativo" podem acessar o sistema. | Garante bloqueio imediato de contas inativadas. | [RF05](../8_requisitos.md#req-rf05), [RF06](../8_requisitos.md#req-rf06), [RNF02](../8_requisitos.md#req-rnf02) |
