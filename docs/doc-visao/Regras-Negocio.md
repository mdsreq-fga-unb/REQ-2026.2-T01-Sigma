# Regras de Negócio
 
As Regras de Negócio (RNs) definem políticas, restrições e diretrizes operacionais indispensáveis ao funcionamento da Creche Estação Vida no sistema SIGMA. Todas as regras estão integradas e vinculadas aos respectivos requisitos e casos de uso no [Catálogo Unificado de Requisitos](8_requisitos.md).

| ID | Regra de Negócio | Justificativa | Requisitos & Casos de Uso Relacionados |
|---|---|---|---|
| <span id="rn01" class="rf-anchor">RN01</span> | Cada aluno pode ter apenas uma matrícula ativa por vez. | Evita duplicidade de registros e conflitos de turma. | [RF08](8_requisitos.md#req-rf08), [RF09](8_requisitos.md#req-rf09) &bull; [UC04](casos-uso/uc04.md) |
| <span id="rn02" class="rf-anchor">RN02</span> | Toda matrícula deve estar vinculada a exatamente uma turma e a uma etapa. | Estrutura organizacional da creche. | [RF13](8_requisitos.md#req-rf13), [RF18](8_requisitos.md#req-rf18), [RF24](8_requisitos.md#req-rf24) &bull; [UC07](casos-uso/uc07.md) |
| <span id="rn03" class="rf-anchor">RN03</span> | Uma matrícula só pode ser considerada ativa após o preenchimento completo das fichas obrigatórias: Termo de compromisso escolar, Termo de Autorização de uso de Imagem, Termo de autorização saída de aluno sem os responsáveis, Socioeconômica e Requerimento de Matrícula. | Garantir conformidade e documentação completa. | [RF09](8_requisitos.md#req-rf09), [RF10](8_requisitos.md#req-rf10) &bull; [UC04](casos-uso/uc04.md), [UC07](casos-uso/uc07.md) |
| <span id="rn04" class="rf-anchor">RN04</span> | Uma turma deve estar obrigatoriamente vinculada a uma etapa existente. | Não pode existir turma solta. | [RF18](8_requisitos.md#req-rf18), [RF24](8_requisitos.md#req-rf24) &bull; [UC06](casos-uso/uc06.md), [UC07](casos-uso/uc07.md) |
| <span id="rn05" class="rf-anchor">RN05</span> | Todos os documentos anexados devem estar em formato PDF. | Padronização e compatibilidade. | [RF14](8_requisitos.md#req-rf14), [RF15](8_requisitos.md#req-rf15) &bull; [UC05](casos-uso/uc05.md) |
| <span id="rn06" class="rf-anchor">RN06</span> | Campos obrigatórios devem ser validados antes do salvamento. | Garantir conformidade. | [RF09](8_requisitos.md#req-rf09), [RF10](8_requisitos.md#req-rf10), [RF13](8_requisitos.md#req-rf13) &bull; [UC04](casos-uso/uc04.md), [UC07](casos-uso/uc07.md) |
| <span id="rn07" class="rf-anchor">RN07</span> | Impedir cadastro de dois alunos com a mesma matrícula ou CPF. | Evita conflito de dados. | [RF08](8_requisitos.md#req-rf08), [RF21](8_requisitos.md#req-rf21) &bull; [UC04](casos-uso/uc04.md), [UC08](casos-uso/uc08.md) |
| <span id="rn08" class="rf-anchor">RN08</span> | Um aluno não pode estar matriculado em duas turmas simultaneamente. | Evitar duplicidade e conflito de horários. | [RF13](8_requisitos.md#req-rf13) &bull; [UC07](casos-uso/uc07.md) |
| <span id="rn09" class="rf-anchor">RN09</span> | A criação de um aviso exige data e autor registrados e só poderá ser publicado quando o assunto e descrição estiverem devidamente preenchidos. | Garante identificação e rastreabilidade. | [RF02](8_requisitos.md#req-rf02) &bull; [UC03](casos-uso/uc03.md) |
| <span id="rn10" class="rf-anchor">RN10</span> | Uma matrícula inativa correspondente a um aluno não poderá ser editada, só pode ser consultada e reativada. | Garante que registros inativos não sejam alterados. | [RF10](8_requisitos.md#req-rf10), [RF11](8_requisitos.md#req-rf11), [RF13](8_requisitos.md#req-rf13), [RF14](8_requisitos.md#req-rf14) &bull; [UC04](casos-uso/uc04.md), [UC05](casos-uso/uc05.md), [UC07](casos-uso/uc07.md) |
| <span id="rn11" class="rf-anchor">RN11</span> | Só turmas e etapas ativas podem receber novos vínculos. | Evita alocar matrículas em estruturas inativas. | [RF13](8_requisitos.md#req-rf13), [RF20](8_requisitos.md#req-rf20), [RF24](8_requisitos.md#req-rf24) &bull; [UC06](casos-uso/uc06.md), [UC07](casos-uso/uc07.md), [UC08](casos-uso/uc08.md) |
| <span id="rn12" class="rf-anchor">RN12</span> | Inativar uma turma ou etapa não elimina os vínculos existentes. | Preserva o histórico de alocação dos alunos. | [RF19](8_requisitos.md#req-rf19) &bull; [UC06](casos-uso/uc06.md), [UC08](casos-uso/uc08.md) |
| <span id="rn13" class="rf-anchor">RN13</span> | Impedir cadastro de duas etapas com o mesmo nome. | Evita conflito de dados. | [RF18](8_requisitos.md#req-rf18), [RF22](8_requisitos.md#req-rf22) &bull; [UC06](casos-uso/uc06.md), [UC08](casos-uso/uc08.md) |
| <span id="rn14" class="rf-anchor">RN14</span> | Impedir cadastro de duas turmas com o mesmo nome dentro da mesma etapa. | Evita conflito de dados. | [RF22](8_requisitos.md#req-rf22), [RF24](8_requisitos.md#req-rf24) &bull; [UC06](casos-uso/uc06.md), [UC08](casos-uso/uc08.md) |
| <span id="rn15" class="rf-anchor">RN15</span> | As alterações na matrícula só são aplicadas após a confirmação. Se a operação for cancelada, os dados não serão salvos. | Evita salvamentos acidentais. | [RF10](8_requisitos.md#req-rf10), [RF23](8_requisitos.md#req-rf23) &bull; [UC04](casos-uso/uc04.md) |
| <span id="rn16" class="rf-anchor">RN16</span> | O sistema deve bloquear o acesso após 5 tentativas consecutivas de login inválidas. | Previne ataques de força bruta e garante a segurança do sistema. | [RF06](8_requisitos.md#req-rf06), [RNF02](8_requisitos.md#req-rnf02) &bull; [UC01](casos-uso/uc01.md) |
| <span id="rn17" class="rf-anchor">RN17</span> | A sessão do usuário deve ser encerrada após 30 minutos de inatividade contínua. | Protege os dados sensíveis dos alunos caso o usuário tenha que sair do sistema e deixar ele logado. | [RF07](8_requisitos.md#req-rf07), [RNF01](8_requisitos.md#req-rnf01), [RNF02](8_requisitos.md#req-rnf02) &bull; [UC01](casos-uso/uc01.md), [UC03](casos-uso/uc03.md) |
| <span id="rn18" class="rf-anchor">RN18</span> | Apenas contas com status "Ativo" podem acessar o sistema. Contas inativadas devem ser bloqueadas do sistema imediatamente. | Garantir que ex-funcionários e/ou pessoas não autorizadas percam acesso total ao sistema e aos dados nele contidos. | [RF05](8_requisitos.md#req-rf05), [RF06](8_requisitos.md#req-rf06), [RNF02](8_requisitos.md#req-rnf02) &bull; [UC01](casos-uso/uc01.md), [UC02](casos-uso/uc02.md), [UC03](casos-uso/uc03.md), [UC08](casos-uso/uc08.md) |
| <span id="rn19" class="rf-anchor">RN19</span> | Cada usuário deverá ser cadastrado no sistema com um e-mail único. | O e-mail atua como chave de identificação no login. E-mails duplicados geram falhas de autenticação e conflitos de contas. | [RF05](8_requisitos.md#req-rf05) &bull; [UC02](casos-uso/uc02.md) |
| <span id="rn20" class="rf-anchor">RN20</span> | O cadastro da senha de um novo usuário do sistema deve conter obrigatoriamente 8 caracteres, incluindo letras, números e caracteres especiais. | Garantir o nível mínimo de segurança contra acessos indevidos, apoiando a proteção de dados exigida pela LGPD. | [RF05](8_requisitos.md#req-rf05), [RNF01](8_requisitos.md#req-rnf01) &bull; [UC02](casos-uso/uc02.md) |
| <span id="rn21" class="rf-anchor">RN21</span> | Um usuário não pode ter sua conta excluída de forma definitiva do banco de dados, apenas inativado. | Preservar a consistência e a rastreabilidade do sistema (manter o registro de quem criou um aviso ou editou uma matrícula, por exemplo). | [RF05](8_requisitos.md#req-rf05) &bull; [UC02](casos-uso/uc02.md) |
| <span id="rn22" class="rf-anchor">RN22</span> | O cadastro de etapa exige obrigatoriamente o nome. O cadastro de turma exige obrigatoriamente o nome e a etapa vinculada. | Sem o nome, não é possível aplicar as regras de unicidade (RN13 e RN14) nem buscar turmas e etapas. | [RF18](8_requisitos.md#req-rf18), [RF24](8_requisitos.md#req-rf24) &bull; [UC06](casos-uso/uc06.md) |
