    UC03 - Gerenciar Quadros de Avisos

    ← Voltar para Casos de Uso

    1. Atores

    Atores principais: Equipe Administrativa (Secretárias, Coordenadoras e Diretora).

    2. Objetivo

    Permitir que a equipe administrativa envie avisos rápidos pelo sistema SIGMA, exiba notificações ativas e apague notificações em seu próprio espaço de forma definitiva, facilitando a comunicação interna, o trabalho em equipe e a coordenação do time da Creche Estação Vida.

    3. Pré-condições

    1. O ator deve estar autenticado no sistema SIGMA.
    2. A conta do ator deve estar com o status "Ativo".
    3. A sessão do ator não pode ter excedido 30 minutos de inatividade contínua.
    4. O ator deve acessar a seção referente ao quadro de avisos na interface.
    5. O sistema deve possuir conexão ativa com o backend (FastAPI/Python).
    6. O backend deve estar integrado ao banco de dados PostgreSQL.

    4. Fluxo Principal

    FP01 - Lançar Aviso no Quadro

    1. O ator acessa a seção do Quadro de Avisos. (RF01)
    2. O sistema identifica o perfil do ator autenticado. (RF01)
    3. O sistema valida se o ator possui perfil da equipe administrativa. (RF01)
    4. O sistema apresenta o formulário de criação de aviso. (RF01)
    5. O ator preenche obrigatoriamente o assunto e a descrição do aviso. (RF02)
    6. O sistema registra automaticamente a data atual e o autor responsável pela criação. (RF02)
    7. O ator confirma a publicação do aviso. (RF02)
    8. O sistema valida os dados obrigatórios informados. (RF02)
    9. O sistema registra o aviso no banco de dados. (RF02)
    10. O sistema disponibiliza o aviso no quadro para todos os usuários autorizados da equipe administrativa. (RF01, RF02)
    11. O sistema exibe uma mensagem de sucesso informando que o aviso foi publicado. (RF02)

    5. Fluxos Alternativos

    FA01 - Exibir Avisos Ativos

    1. O ator acessa a página inicial ou a seção do quadro de avisos. (RF03)
    2. O sistema identifica o perfil do ator autenticado. (RF03)
    3. O sistema busca os avisos ativos disponíveis no banco de dados, ordenados por data. (RF03)
    4. O sistema exibe a lista de notificações ativas no quadro de avisos. (RF03)
    5. O ator visualiza os avisos. (RF03)

    FA02 - Apagar Aviso de Forma Definitiva

    1. O ator acessa o quadro de avisos com as notificações ativas. (RF03, RF04)
    2. O ator seleciona um aviso existente no seu próprio espaço. (RF04)
    3. O ator aciona a opção de apagar/excluir. (RF04)
    4. O sistema solicita a confirmação da exclusão definitiva. (RF04)
    5. O ator confirma a exclusão. (RF04)
    6. O sistema remove o aviso da visualização do ator de forma definitiva. (RF04)
    7. O sistema atualiza o quadro de avisos e exibe uma mensagem de sucesso. (RF04)

    FA03 - Cancelar Lançamento de Aviso

    1. Durante o preenchimento de um novo aviso, o ator aciona a opção de cancelar ou fechar a janela. (RF02)
    2. O sistema descarta as informações não salvas. (RF02)
    3. O sistema retorna o ator para a visualização padrão do quadro de avisos. (RF02)
    4. Nenhum dado é registrado no banco de dados. (RF02)

    6. Fluxos de Exceção

    FE01 - Interface Indisponível para o Perfil do Ator

    1. Um usuário não autorizado tenta acessar a rota de lançamento de avisos. (RF01)
    2. O sistema identifica que o perfil não possui permissão. (RF01)
    3. O sistema bloqueia o acesso e não exibe a funcionalidade de gerenciamento do quadro. (RF01)

    FE02 - Dados Obrigatórios Ausentes

    1. O ator tenta publicar um aviso sem preencher o assunto e/ou a descrição. (RF02)
    2. O sistema identifica a ausência dos dados obrigatórios. (RF02)
    3. O sistema impede a publicação do aviso. (RF02)
    4. O sistema destaca os campos inválidos e exibe mensagem orientando o preenchimento correto. (RF02)

    FE03 - Falha de Conectividade

    1. O ator tenta publicar, listar ou apagar um aviso sem conexão com o backend. (RF02, RF03, RF04)
    2. O sistema não consegue concluir a operação. (RF02, RF03, RF04)
    3. O sistema exibe uma mensagem de falha de conexão. (RF02, RF03, RF04)
    4. O sistema orienta o ator a tentar novamente mais tarde. (RF02, RF03, RF04)

    FE04 - Sessão Expirada por Inatividade

    1. O ator tenta confirmar o lançamento de um aviso ou excluí-lo após 30 minutos de inatividade. (RF07)
    2. O sistema identifica que a sessão do usuário expirou. (RF07)
    3. O sistema impede a operação. (RF07)
    4. O sistema encerra a sessão, descarta as alterações não salvas e redireciona o ator para a tela de login. (RF07)

    7. Regras de Negócio

    ID Regra de Negócio Justificativa Requisitos Relacionados
    RN09 A criação de um aviso exige data e autor registrados e só poderá ser publicado quando o assunto e descrição estiverem devidamente preenchidos. Garante identificação e rastreabilidade. RF02
    RN17 A sessão do usuário deve ser encerrada após 30 minutos de inatividade contínua. Protege os dados sensíveis dos alunos caso o usuário tenha que sair do sistema e deixar ele logado. RF07, RNF01, RNF02
    RN18 Apenas contas com status "Ativo" podem acessar o sistema. Contas inativadas devem ser bloqueadas do sistema imediatamente. Garantir que ex-funcionários e/ou pessoas não autorizadas percam acesso total ao sistema e aos dados nele contidos. RF05, RF06, RNF02

    8. Requisitos Relacionados

    Requisito / Característica Relação com a UC
    RF01 - Disponibilizar Quadro Permite que o ambiente do quadro de avisos seja acessível para a equipe.
    RF02 - Lançar Avisos Permite que os atores publiquem novas notificações para a equipe administrativa.
    RF03 - Exibir Avisos Garante a visualização das notificações ativas no sistema.
    RF04 - Apagar Avisos Permite a remoção definitiva de um aviso do espaço visual.
    RF05 - Gerenciar Usuários Relação indireta para garantir bloqueio de inativos (RN18).
    RF07 - Encerrar Sessão Relação para tratamento de inatividade da sessão (RN17).
    CP6 - Avisos Rápidos O caso de uso implementa diretamente a funcionalidade de postagem de avisos administrativos do sistema.

    9. Protótipo
